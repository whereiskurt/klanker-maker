Architecture · infrastructure-as-code invocation path

Who runs Terraform, from where, and where the state actually lives

You never invoke terraform yourself, and no local state file exists anywhere in the project. km resolves km-config.yaml into KM_* environment variables, sets the working directory to one committed unit, and execs a pinned terragrunt. The same tree, the same binaries and the same S3 backend are used again inside a Lambda for remote creates — which is why the deploy surface for a schema change includes rebuilding that Lambda.
