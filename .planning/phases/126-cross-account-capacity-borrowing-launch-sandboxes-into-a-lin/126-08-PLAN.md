<objective>
Make teardown work across the account boundary in both places it happens: the operator's
`km destroy` (including the cold-clone fallback) and the unattended expiry Lambda.

Purpose: REQ-126-TEARDOWN, which the roadmap marks NOT OPTIONAL. Without it a GPU box
costing roughly ten dollars an hour lands in an account `km list` does not watch and
never auto-expires. Research found the gap is larger than the design spec stated: the
cold-clone path's synthesized minimal configuration is missing the launch account, AND
the tag-based discovery that runs BEFORE it is scoped to the home account, so a linked
sandbox is reported as not found before the synthesis branch is ever reached.

Output: an account-aware discovery order in `km destroy`, a conditional assume-role block
in the Lambda's rendered configuration, and the Terraform grant that lets the Lambda do it.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| expiry Lambda (home account) → linked account | an unattended, scheduled, credential-holding path across the account boundary |
| sandbox DynamoDB row → teardown target selection | the row decides which account gets a destroy run against it |
| Lambda environment variable → launcher ARN list | operator-controlled configuration that becomes an assume-role target |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-126-41 | Denial of Service | unreapable linked instance | critical | mitigate | Both teardown paths are made account-aware in this plan, and the roadmap forbids deferring either. An unreaped GPU instance bills continuously in an account the operator's inventory does not list. |
| T-126-42 | Spoofing | silent home-account destroy attempt | high | mitigate | An unknown link name or a failed external-id read aborts the teardown with a logged error rather than rendering a home-account provider — which would report success while the instance kept running. |
| T-126-43 | Elevation of Privilege | Lambda assume-role grant scope | high | mitigate | The grant names specific launcher role ARNs from configuration rather than a wildcard, and emits no statement at all when no link is configured. |
| T-126-44 | Information Disclosure | external id in Lambda memory and rendered file | medium | mitigate | Read per teardown into a temporary working directory that is removed by the existing deferred cleanup; never logged; never written to durable storage. |
| T-126-45 | Tampering | account-scoped tag discovery masking a live instance | high | mitigate | The sandbox row is consulted before the tag scan, and the scan's not-found is non-fatal only for a row that declares a linked account — the home-account failure mode is preserved exactly. |
| T-126-46 | Repudiation | prefix-label drift in the rendered configuration | low | mitigate | The hardcoded label is replaced by the resource-prefix helper; the existing ttl-handler tests plus the byte-identity assertion bound the blast radius. |
</threat_model>
