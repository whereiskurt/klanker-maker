<objective>
Land the mechanism the whole phase rests on: a conditional `generate "provider"`
override in the sandbox terragrunt template that emits an `assume_role` block when
the compiler has written a `launch_account` local into `service.hcl`, plus the
compiler side that writes those locals — and the regression guards that prove both
the active and the dormant path.

Purpose: REQ-126-LAUNCH's provider mechanism. RESEARCH.md established by direct
execution against the pinned terragrunt v0.99.1 that a same-labeled `generate` block
in parent and child **hard-errors** under the default merge strategy. That is a static
structural collision: it fires on every sandbox render, cross-account or not, dormant
or not. This is simultaneously the highest-risk change in the phase and the one with
no existing automated coverage — RESEARCH.md confirms the repo has no automated
coverage of terragrunt HCL behavior at all.

Output: the template change, the compiler locals, and two layers of regression test
(a always-on structural test and a terragrunt-render test).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service.hcl (on operator disk) → generated provider.tf | the compiler-written `launcher_external_id` local is a resolved secret sitting in a plaintext file inside the sandbox working directory |
| terragrunt provider → account B STS | the generated `assume_role` block is the only mechanism by which A reaches B |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-126-05 | Denial of Service | `include "root"` merge strategy | high | mitigate | A missing `merge_strategy = "deep"` breaks every sandbox render, cross-account or not — a total create outage. Mitigated by the always-on structural test in Task 3(A) plus the negative control the executor runs. |
| T-126-06 | Tampering | generated provider.tf version pins | high | mitigate | Deep merge replaces root's generate block entirely; silently dropping `required_providers` would un-pin the AWS provider for every sandbox and let a future provider release change resource behavior. Mitigated by asserting root's pins are present in the child, in Task 3(A). |
| T-126-07 | Information Disclosure | `launcher_external_id` in service.hcl | medium | mitigate | The ExternalId is written to a local file under the operator's own repo, at the same trust level as the operator's AWS credentials. It is never logged (compiler field doc comment) and is never emitted for a profile without a launch account. Not stored in git — sandbox dirs are generated, not committed. |
| T-126-08 | Spoofing | conditional `assume_role` emission | high | mitigate | The block emits only when the compiler wrote a non-empty `launch_account` local; the `try(...)` default keeps a missing local from producing a partially-formed assume_role. Task 2 Test 1 and Task 3's dormancy equality assert the empty case emits nothing. |
| T-126-09 | Elevation of Privilege | state backend | medium | accept | The `remote_state` override is deliberately untouched: state stays in the home account's S3 backend under home credentials while only the provider assumes into B. This is the proven SCP-stack split and is the reason a compromised B cannot reach A's state. |
</threat_model>
