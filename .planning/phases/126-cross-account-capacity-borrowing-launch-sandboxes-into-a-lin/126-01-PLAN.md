<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator YAML → km CLI | `km-config.yaml` and profile YAML are operator-authored but are the sole source of the cross-account target; a wrong or attacker-supplied link name selects which AWS account is reached |
| km-config.yaml → SSM | the link record stores only an SSM path for the ExternalId, never the secret itself |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-126-01 | Information Disclosure | `LaunchAccountConfig` | high | mitigate | The struct carries `ExternalIDSSM` (an SSM SecureString **path**) and has no plaintext-secret field at all. There is deliberately no `ExternalID string` member, so a secret cannot be persisted into km-config.yaml through this type. |
| T-126-02 | Spoofing | `ValidateLaunchAccountLink` | medium | mitigate | An unknown link name is a hard validation error before any AWS call, so a typo'd or injected profile field cannot silently fall through to the home account or to an unregistered ARN. |
| T-126-03 | Tampering | config merge-list | medium | mitigate | The merge-list regression test (Task 1, Test 1) fails if the `"launch_accounts"` entry is removed — a silently-dropped block would make every downstream link lookup miss and mask misconfiguration. |
| T-126-04 | Elevation of Privilege | schema `additionalProperties: false` | low | accept | The runtime object already rejects undeclared keys; adding one optional string does not widen the accepted surface. |
</threat_model>
