## Live verification

**Status as of this record: NOT YET RUN.** This section is the checklist the operator runs
with two real AWS credential sets. No step below has been executed in this environment — no
AWS mutation was performed while producing the pre-flight gate above, and no
`launch_accounts:` link exists anywhere in this project's history (126-03, 126-06, 126-07,
126-08, and 126-09 each independently flagged the same gap in their own SUMMARY.md files: no
synthetic/mocked substitute for a second real AWS account was available during Waves 1–4).

Every row/step below records an **expected** outcome only. Do not read any row as "passed" —
the "Actual" column is intentionally blank pending the operator running this checklist.

### Prerequisites

1. Administrator credentials for the capacity (target) account, available as a named AWS
   profile.
2. Home-account credentials, available as the usual profile
   (`AWS_PROFILE=klanker-application` for this install per project convention).
3. GPU vCPU quota (`L-DB2E81BA`, "Running On-Demand G and VT instances") has headroom in the
   **target** account and region — verified directly in that account's Service Quotas
   console/API, not the organization's management console (a different account's quota has
   already cost this project two phases of deferred verification per CLAUDE.md § Phase 122 /
   Phase 124).
4. The operator binary and Lambdas have been rebuilt and applied per
   `docs/cross-account-capacity-borrowing.md` § Deploy surface, in the stated order:
   `make build` → `make build-lambdas` → `km init --dry-run=false`.

### Containment proof — the 8-row `simulate-principal-policy` matrix (run first, no spend)

Each row is one `aws iam simulate-principal-policy --policy-source-arn <launcher-role-arn>
--action-names <action> [--resource-arns <arn>] [--context-entries ...]` call against the
**live** launcher role created by `km account add`. A single unexpected `allowed` verdict on
any row is a blocking finding — stop and report; do not proceed to the live create steps.

| # | Simulated call | Expected verdict | Proves | Actual verdict |
|---|---|---|---|---|

| 2 | `ec2:RunInstances` with instance type NOT in the allowlist | `implicitDeny` | `ec2:InstanceType` condition is enforced | _(pending)_ |
