<objective>
Wire the link record into both create paths and into the capacity gate: resolve the
link, source network placement from it, build the second assumed-role AWS config for
the quota check, namespace the capacity store, and record the account on the sandbox row.

Purpose: REQ-126-LAUNCH's Go half and REQ-126-CAPACITY. Local and remote create land
together because the GPU quota gate fails fast BEFORE the AZ sweep — a gate that read
the home account's headroom would abort every linked GPU create, so the capacity change
is indivisible from the launch change.

Output: a single link-resolution helper used by three call sites, plus the create-flow
and capacity-command changes that consume it.
</objective>

## Decisions recorded by this plan

- **The linked account's subnets are treated as always-public.** That account's network is
  lean by design and has no NAT gateway concept at all, so the NAT-served-availability-zone
  filter the home account uses is passed as nil for any link-scoped ranking. Passing a NAT
  filter derived from a network that has no NAT would drop every zone.
- **The account carries its region.** When a link is in effect, region, subnets, security
  group and (when requested) the shared filesystem id all come from the link record. A
  conflicting region in the profile is ignored with a warning rather than an error, because
  the profile is not wrong — the link simply wins.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| home account process → linked account STS | the assumed-role config built here is the only Go-side crossing |
| home parameter store → in-memory external id → service.hcl | the secret's path from storage to the generated terragrunt local |
| shared capacity table → per-account rows | one table, two accounts, separated only by the key namespace |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-126-29 | Spoofing | capacity gate reading the wrong account | high | mitigate | The assume-role failure path aborts the create and the capacity report instead of falling back to the home account's clients. Task 2 Test 5 and Task 3 Test 6 assert it, and the acceptance criteria require the executor to grep the function for any continuing branch. |
