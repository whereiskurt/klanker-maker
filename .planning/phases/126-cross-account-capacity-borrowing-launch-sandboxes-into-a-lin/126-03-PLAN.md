<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| account A process → account B STS | `AssumeRoleConfig` is the only Go-side path that crosses the account boundary in this phase |
| DynamoDB row (A) → teardown decision | `launch_account` on the sandbox row is what tells `km destroy` and the ttl-handler which account holds the instance |
| shared capacity table (A) → per-account rows | one table serves both accounts; only the key value separates them |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-126-10 | Spoofing | `AssumeRoleConfig` fail-open | high | mitigate | Explicitly fail-closed: no fallback to the caller's credentials, argument validation rejects an empty role ARN or region, and Task 1 Test 2 asserts the failure surfaces. A fail-open helper would gate a linked-account GPU launch on the home account's quota. |
| T-126-11 | Spoofing | ExternalId omission | high | mitigate | The external id is threaded as a first-class parameter and set as a pointer only when non-empty, so a caller that has one always sends it. The confused-deputy protection lives in B's trust policy (plan 04), which requires the condition; a request without it is rejected by AWS, not silently downgraded. |
| T-126-12 | Denial of Service | dropped `launch_account` attribute | high | mitigate | A stripped attribute leaves a running GPU instance (~$10.49/hr) unreachable by both `km destroy` and the ttl-handler. Mitigated by symmetric marshal/unmarshal, the double-round-trip test, and the call-site-count acceptance criterion. |
| T-126-13 | Tampering | capacity-store cross-contamination | medium | mitigate | Namespacing happens in the store constructor only. The `instanceType` argument that also feeds the EC2 offerings filter is never rewritten, so a namespaced value cannot leak into an AWS API call. |
| T-126-14 | Information Disclosure | STS session name / logs | low | accept | The role session name is a fixed km identifier carrying no secret. The external id is never logged by this helper. |
| T-126-SC | Tampering | Go module `stscreds` | low | accept | Subpackage of `github.com/aws/aws-sdk-go-v2/credentials`, already a hash-pinned indirect dependency in this repo's go.sum, published by the same AWS org as every other SDK client already imported. RESEARCH.md § Package Legitimacy Audit records the OK verdict; no `[ASSUMED]`/`[SUS]` package is introduced, so no blocking human checkpoint applies. |
</threat_model>
