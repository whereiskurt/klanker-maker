## 0. Deploy

Prerequisite discovered before any UAT step ran, and worth recording because it
would have silently invalidated the whole exercise.

A full `km init --dry-run=false` had just been run from the main checkout, but
its `./km` was commit `5b3f11fc` — a docs-only commit from 12:54 that predates
**both** Phase 133 waves. Its `sidecarBuilds()` therefore never listed
`km-secretsd`, `km-env` or `km-creds`; they were not skipped and did not fail to
upload, they were never candidates. The run printed no error and exited 0.

Verified state after that run:

| object | timestamp | meaning |
|---|---|---|
| `sidecars/km-creds` | absent | fenced sandbox `credential_process` → missing binary |
| `sidecars/km-secretsd` | 19:35 | Wave 1, no assertion 6 |
| `sidecars/km-env` | 19:36 | Wave 1 |
| `sidecars/km-presence` | 22:32 | **no signal 8** — verified by symbol probe, below |
| `toolchain/km` | 19:38 | Wave 1; cold-create cannot compile a fenced profile |
| `binaries/herdr` | 19:37 | present, untouched |

The km-presence probe (the one that matters for this UAT) — S3 object vs a local
build from this branch:

| symbol | deployed | branch build |
|---|---|---|
| `checkHerdrPaneBusy` | 0 | 2 |
| `herdrPaneIsBusy` | 0 | 2 |
| `foreground_process_group_id` | 0 | 3 |

**Consequence for this UAT:** any sandbox created against that state has no
signal 8 at all. Steps 4 and 5 would have produced a result that looked like a
pass or a fail but measured nothing. Recorded here because the same trap will
catch the next person.

**Repair sequence used:**

1. Operator: `make build` + `km init --dry-run=false` from the main checkout,
   deploying Phase 133 Wave 2 off main code.
2. This branch: `km init --sidecars` from the merged worktree, layering
   signal-8 `km-presence` and re-mirroring `binaries/herdr`. Safe in this order
   only — the reverse lets main's apply clobber signal 8 again.

- [ ] **Step 0.1** — operator apply complete, `sidecars/km-creds` present

- [ ] **Step 0.3** — deployed `km-presence` carries `checkHerdrPaneBusy`;

## 1. Steps

- [ ] **Step 1: Deploy + mirror check** — `aws s3 ls s3://…/binaries/herdr`
- [ ] **Step 2: Fragment installs at boot** — `km create profiles/uat-herdr.yaml herdruat --wait`,
      then `km herdr status herdruat` reports herdr present with no ensure-install
      and no pre-signal-8 warning
- [ ] **Step 2b (NEW — the fragment proof): the S3 path is the ONLY path.**
      `profiles/uat-herdr.yaml` does not extend `base/userinit` and its allowlist
      omits GitHub, so `/usr/local/bin/herdr` existing proves the fragment's
      fetch ran. Assert `~sandbox/.local/bin/herdr` is ABSENT and that a direct
      GitHub fetch from the box fails.
- [ ] **Step 3: ensure-install path** — remove the binary, `km herdr status`
      fails naming `km herdr start`, then `km herdr start` installs it
- [ ] **Step 4: signal 8 positive (headless)** — detached busy pane keeps the box
      alive past `idleTimeout` (10m), and heartbeats stop when the job is killed
- [ ] **Step 5: signal 8 negative — the gate.** Idle panes, headless server still
      running, every `km shell` closed. Box must stop on schedule. **If it stays
      alive, idle teardown is broken fleet-wide — do not merge.**
- [ ] **Step 5b: OPERATOR-RUN** — interactive `herdr --remote km-<id>` attach,
      `ctrl+b q` detach, reattach
- [ ] **Step 6: lifecycle claim** — `km pause`/`km resume` keeps pane processes;
      `km stop`/`km resume` does not
- [ ] **Step 7: record + tear down**
