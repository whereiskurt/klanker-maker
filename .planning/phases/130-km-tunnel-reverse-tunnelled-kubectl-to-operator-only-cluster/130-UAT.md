# Phase 130 — live UAT: `km tunnel`

**Status: NOT YET RUN.** Phase 130 ships code-complete with live UAT pending.

Nothing in this phase can be exercised on the development machine — it has no VPN, no
cluster, and no kubectl. This script is fixed **before** first contact so bring-up is a
sequence rather than an improvisation, and so a failure localises to one leg on a machine
with no debugger.

Steps escalate deliberately: step 1 needs nothing at all, step 2 needs the VPN, step 3
adds a sandbox. Do not skip ahead — the cheap steps are where the likely bugs are.

## Prerequisites on the UAT machine

- [ ] `km --version` reports **v0.8.6** or later
- [ ] OpenVPN connected
- [ ] `kubectl --context k8s1 get ns` works **directly on this machine** (km forwards a
      working kubectl; it cannot repair a broken one)
- [ ] A running sandbox, `km list` shows it, and `~/.km/keys/<id>` exists here
- [ ] The sandbox's profile did not set `spec.runtime.vscode.enabled: false`

Record the real values once and reuse them:

```
SANDBOX=
CONTEXT=k8s1
```

## Step 1 — `--dry-run` (no VPN needed, no sandbox needed)

```bash
km tunnel "$SANDBOX" --context "$CONTEXT" --dry-run
```

**Expect:** a report naming the resolved context, the cluster address, the TLS server
name, your credential plugin with its args, the full ssh command, and the kubeconfig
that would be written.

**Verify by hand — this is the whole point of the step:**

- [ ] `Cluster address` matches `clusters[].cluster.server` in your own kubeconfig,
      host **and** port
- [ ] `TLS server name` matches your `tls-server-name`, or the server hostname if you
      have none
- [ ] `Credential plugin` matches your `users[].user.exec.command` and args exactly
- [ ] The ssh command contains `-o ExitOnForwardFailure=yes`
- [ ] The printed kubeconfig's `server:` is `https://127.0.0.1:6443` and does **not**
      contain the real cluster hostname
- [ ] The printed kubeconfig's exec block has `interactiveMode: Never`

## Optional — collision behaviour

With one tunnel already open, from a second terminal:
