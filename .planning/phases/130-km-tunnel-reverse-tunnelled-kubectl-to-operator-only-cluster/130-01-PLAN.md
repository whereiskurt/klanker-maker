<objective>
Add `pkg/kubetunnel` with kubeconfig parsing and context resolution: given a
kubeconfig path set (or `$KUBECONFIG`, or `~/.kube/config`) and a context name,
produce a `Target` carrying everything the rest of the phase needs — the real
cluster host and port, the TLS server name, and the exec stanza to run locally.

Purpose: this is the single place the operator's real cluster is described, and
it is the largest chunk of logic that IS unit-testable without a VPN or cluster.
Everything downstream is argv and file text derived from a `Target`.

Output: `pkg/kubetunnel/kubeconfig.go`, table-driven tests, four fixtures.
</objective>

## Artifacts

New package `pkg/kubetunnel`. Types:

- `type ExecConfig struct { APIVersion, Command string; Args []string; Env []ExecEnv; InteractiveMode string }`
- `type ExecEnv struct { Name, Value string }`
- `type Target struct { Context, ServerHost string; ServerPort int; TLSServerName string; Exec *ExecConfig }`

Functions:

- `func KubeconfigPaths(override string) []string` — override wins; else `$KUBECONFIG`
  split on `os.PathListSeparator`; else `~/.kube/config`.
- `func Load(paths []string) (*Kubeconfig, error)` — parse and merge; first file wins per key.
- `func (k *Kubeconfig) Resolve(contextName string) (*Target, error)`

  <behavior>
    - `Resolve("k8s1")` on `simple.yaml` yields ServerHost `k8s1.corp`, ServerPort 6443, TLSServerName `k8s1.corp`, and a non-nil Exec whose Command is the fixture's.
    - `Resolve` on `no-tls-server-name.yaml` falls back to the server URL hostname for TLSServerName.
    - `Resolve` on a server URL with no port (`https://k8s1.corp`) yields ServerPort 443.
    - `Resolve` on a server URL with an explicit non-standard port yields that port.
    - `Resolve("nope")` errors naming the missing context and listing available context names.
    - A context pointing at an absent cluster errors naming the cluster; same for an absent user.
    - A user with no exec stanza errors explaining that km tunnel requires an exec-based (OIDC) user.
    - `exec-with-env-args.yaml` round-trips args and env verbatim into Target.Exec.
    - A non-https server URL is rejected with a clear error.
  </behavior>
  <action>
    Implement `Resolve`. Parse the cluster server with `net/url`; require scheme
    `https`. Derive port from `url.Port()`, defaulting to 443 when empty — the box
    kubeconfig's `-R` spec always needs an explicit port, and a missing one would
    otherwise render `host:`.

    TLSServerName falls back to the server URL's hostname when the cluster does not
    set `tls-server-name`. This is what makes the loopback kubeconfig work without
    touching `/etc/hosts` on the box, so it must never be empty.

    Carry `Exec` verbatim — no expansion of args or env. The broker in plan 02 runs
    it as-is; interpreting it here would be a second place to be wrong about a
    plugin this repo cannot test.

    Every error names the offending key and, for a missing context, lists what IS
    available — the operator will be reading these on a machine with no debugger.
  </action>
