<objective>
Add the laptop-side credential broker: a unix-socket HTTP server that, on request,
runs the operator's existing kubectl exec plugin and returns its stdout unchanged.

Purpose: this is what keeps every durable credential on the laptop. The sandbox
gets a short-lived bearer token for one cluster and never an AWS credential, a
refresh token, or a VPN route. The broker is deliberately the dumbest component in
the phase — the exec plugin's real behaviour cannot be verified from this machine,
so the less the broker assumes, the less can be wrong on first contact.

Output: `pkg/kubetunnel/broker.go` plus tests driven by stub plugin scripts.
</objective>

## Artifacts

```go
type Broker struct { /* socketPath, dir, srv, exec *ExecConfig, log io.Writer */ }

func NewBroker(exec *ExecConfig, logOut io.Writer) (*Broker, error) // creates 0700 dir + socket path
func (b *Broker) SocketPath() string
func (b *Broker) Serve() error   // non-blocking listen; returns once accepting
func (b *Broker) Close() error   // shuts down and removes the dir
```

An injectable `runner func(ctx, *ExecConfig) (stdout []byte, stderr []byte, err error)`
field on `Broker` (defaulting to the real `os/exec` implementation) is what makes this
testable without a plugin installed.

  <name>Task 1: Unix-socket server with an injectable plugin runner</name>
  <files>pkg/kubetunnel/broker.go, pkg/kubetunnel/broker_test.go</files>

  </read_first>
  <behavior>
    - `NewBroker` creates a directory with mode 0700 and a socket path inside it.
    - `Serve` then `Close` leaves no directory and no socket file behind.
    - A GET to the socket returns the runner's stdout byte-for-byte, including trailing newline and any non-JSON content.
    - A runner returning a non-nil error yields HTTP 500 whose body contains the runner's stderr.
    - The response is NOT re-serialised: a stdout of `{"a":1}   ` (trailing spaces) comes back with those spaces intact.
    - Each successful mint writes one line to the broker's log writer; a failed mint writes one too, marked as such.
    - `Close` is idempotent — calling it twice does not panic or error.
  </behavior>
  <action>
    Create `pkg/kubetunnel/broker.go`. `NewBroker` makes a temp dir via
    `os.MkdirTemp` and `os.Chmod`s it to 0700 (MkdirTemp is already 0700 on Unix,
    but assert it — the socket's only access control is the filesystem).

    Serve on `net.Listen("unix", socketPath)` with an `http.Server`; one handler on
    `/token` and a catch-all returning 404. The handler calls `b.runner`, writes
    stdout verbatim with `Content-Type: application/json`, and on error writes 500
    with the stderr text.

    Explicitly do NOT read the request body or any `KUBERNETES_EXEC_INFO` the shim
    might send. Document why in a comment: the box's kubeconfig describes the fake
    `127.0.0.1` endpoint, so forwarding its cluster info to a plugin that expects
    the real cluster would be actively misleading. Plugins needing
    `provideClusterInfo: true` are unsupported in v1; kubelogin does not need it.

    Log one line per mint to `b.log`, prefixed so it is distinguishable in the
    operator's terminal amid ssh output.

    `Close` must `os.RemoveAll` the dir and tolerate being called twice — plan 03
    defers it and may also call it on an error path.
  </action>

  <behavior>
    - The default runner executes ExecConfig.Command with its Args and returns stdout and stderr separately.
    - ExecConfig.Env entries are appended to the inherited environment, not replacing it — the plugin needs $HOME and $PATH to find its own token cache.
    - A command that does not exist returns an error mentioning the command name.
    - The runner honours context cancellation.
  </behavior>
  <action>
    Implement `defaultRunner` using `exec.CommandContext`. Set `cmd.Env =
    append(os.Environ(), ...)` for each `ExecEnv` — inheriting is load-bearing:
    kubelogin resolves its token cache under `$HOME` and finds its browser opener
    via `$PATH`, so a clean environment would break the refresh flow the operator
    depends on.

    Leave the plugin's stdin unattached. Do not allocate a TTY: the plugin opens a
    browser rather than prompting, and a TTY would be a lie about interactivity we
    cannot honour from inside an HTTP handler.

    Test with a stub script written to a temp dir at test time (`#!/bin/sh` echoing
    fixed stdout/stderr and exiting with a chosen code) so no real plugin is needed.
  </action>
