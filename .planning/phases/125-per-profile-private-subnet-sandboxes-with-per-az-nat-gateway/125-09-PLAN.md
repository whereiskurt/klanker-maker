<objective>
Document the phase, gate on the full test suite, and run the eight-step live UAT against
real AWS.

Purpose: the deploy surface here has a load-bearing ORDER — the operator `km` binary
carries the new `NetworkOutputs` extraction and the `KM_NAT_GATEWAY_ENABLED` export, so a
stale binary silently skips both and the NAT toggle appears to do nothing. Half of this
phase's behaviour (an additive-only plan, a real absence of a public IPv4, an egress source
IP equal to a NAT EIP, an ICE rotation across NATs, a ttl-handler auto-destroy across a
module-version boundary, a clean teardown) can only be proved against live AWS.

Step 6 of the UAT discharges the phase's highest-risk unknown. CONTEXT.md's Risk Summary
demanded the frozen-`v1.0.0` ttl-handler destroy stub be resolved "as an investigation
task, not as an assumption". RESEARCH.md Finding 1 resolves it analytically at HIGH
confidence, but Finding 1 ALSO establishes that the ordinary `km destroy` path reuses the
sandbox's original create-time `terragrunt.hcl` and therefore never crosses module
versions at all — so a teardown-only UAT would leave the actual drift path untested. Only
the Lambda-driven TTL expiry exercises it.

Output: an operator document, a CLAUDE.md phase block, and a completed UAT record.
</objective>
