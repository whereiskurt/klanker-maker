<objective>
Make `km init` the producer of `KM_NAT_GATEWAY_ENABLED`, the reader of the new network
outputs, the printer of the NAT cost, and the enforcer of the refuse-to-disable guard.

Purpose: this is the one file that owns all four `km init`-side concerns, and they must
land together — the config key from Plan 03 is inert until it is exported, and the module
outputs from Plan 01 are invisible to `km create` until they are extracted here.

Output: `NetworkOutputs` gains two fields and two extraction calls; the env-export block
gains one entry with a drift WARN; the network module's post-apply display gains NAT
information; and a new guard file refuses a NAT-disabling apply while private sandboxes
are running.
</objective>

Enabling NAT is never blocked, keeping the additive direction friction-free. |

| T-125-20 | Spoofing | guard bypass via unavailable lister | low | accept | With no DynamoDB access the guard WARNs and proceeds rather than locking the operator out of `km init`. Accepted: the operator running `km init` already holds the credentials to destroy this infrastructure directly. |
