### Deploy sequence (run first, in this exact order — the order is load-bearing)

- [ ] `make build` — operator binary; carries the new network-outputs extraction and the
  `KM_NAT_GATEWAY_ENABLED` export. A stale binary silently skips both.
- [ ] `make build-lambdas` — create-handler carries the new compiler, profile schema, and the
  `infra/templates` bundle with the per-substrate version pin.
- [ ] `km init --dry-run=false` — full terragrunt apply. Do **NOT** use `km init --sidecars`:
  no sidecar binary changed, and the NAT/EIP/route resources need a full apply.

Note on this apply's expected plan: it will ALSO show the one-time private-route-table split
(one `moved` plus three additional empty route tables plus repointed associations). That part
is unconditional — it comes from sourcing network v1.1.0, not from the NAT toggle — and is
additive/non-destructive. See `docs/private-subnet-nat.md`.
