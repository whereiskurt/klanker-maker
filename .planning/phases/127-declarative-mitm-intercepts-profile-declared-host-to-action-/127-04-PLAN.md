<objective>
Give `km validate` the five intercept errors and the three intercept warnings the
design locks, so a rule that can never fire is caught at authoring time rather
than discovered as silence on a live sandbox.

Purpose: three of the ways an intercept fails are invisible at runtime — a
platform handler wins, the deny gate wins, or the name never resolves. Each
produces a rule that looks configured and does nothing. A warning is the only
place that gap can be surfaced without letting the feature quietly widen egress
policy.

Output: intercept rules inside `ValidateSemantic` plus a test per error and per
warning.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| profile author → platform guarantees | An authored rule could name a host whose handling the platform reserves for metering or repo filtering. |
| validate output → operator | A warning is the only signal that a configured rule will never fire. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-127-01 | Elevation of Privilege | platform-reserved overlap warning | medium | mitigate | The reserved list is sourced from the sidecar files that own each host, and the warning states that the platform handler wins so the author does not assume the rule took effect. |
| T-127-11 | Repudiation | denied-host overlap warning | medium | mitigate | The warning uses `netpolicy.Match`, the same matcher the runtime deny gate uses, so validate-time and run-time can never disagree about which rules are dead. |
| T-127-09 | Information Disclosure | DNS reachability warning | medium | mitigate | The warning exists precisely so the alternative — silently adding intercept hosts to `allowedDNSSuffixes` — is not taken; declaring a rule must never widen what a sandbox can resolve. |
| T-127-12 | Denial of Service | validation strictness | low | accept | Reserved, denied, and unreachable hosts stay warnings rather than errors; an operator may knowingly ship a dead rule and must not be blocked from doing so. |
| T-127-SC | Tampering | npm/pip/cargo installs | high | accept | No package installs and no new dependency beyond the in-repo `pkg/netpolicy`; the Package Legitimacy Gate has nothing to audit. |
</threat_model>
