## Deploy preamble (read before running any live step)

Run, in this exact order:

```bash
make build
make build-lambdas
km init --dry-run=false
```

**`km init --sidecars` alone is not merely insufficient — it is actively harmful mid-rollout.**
It rebuilds and uploads the sidecar binaries but does NOT refresh the create-handler zip that
renders the `mitm.conf` user-data drop-in. Running `--sidecars` alone drops the built-in Rickroll
on a live box (the new `km-http-proxy` binary has no `KM_MITM_INTERCEPTS` to read) while leaving
the profile schema unable to declare it back until the full sequence completes. See
`docs/mitm-intercepts.md` § Deploy surface.

**Existing sandboxes keep today's behaviour until `km destroy && km create`.** Every step below
therefore needs a **freshly created** box — an already-running sandbox will not pick up either
the new opt-in default or the demo profile's rules.
