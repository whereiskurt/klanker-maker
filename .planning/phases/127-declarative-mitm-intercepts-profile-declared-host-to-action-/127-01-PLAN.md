<objective>
Add the `spec.network.mitm.intercepts` profile surface: the four Go types, the
`NetworkSpec.MITM` field, the JSON-schema subtree, and the by-name last-wins
collapse that makes `enabled: false` able to switch off a rule inherited through
`extends:`.

Purpose: Phase 117 merges profile lists by union, so without a name-collapse an
inherited intercept can never be turned off and `enabled` is dead weight. This
plan is the foundation both the compiler (plan 03) and validation (plan 04)
build on.

Output: `pkg/profile/mitm.go` with the collapse/enabled accessors, new structs in
`types.go`, the schema subtree, three inheritance fixtures, and unit tests.
</objective>

  <action>
    Create `pkg/profile/mitm.go` (package `profile`) with the five functions listed in
    the artifacts section above.

    `CollapseIntercepts` implements the locked override rule: resolve by `name`,
    last-wins, WHOLE ENTRY. An override replaces the inherited entry outright rather
    than merging field-by-field. Document that explicitly in the function comment, with
    the consequence spelled out: `name` plus `enabled: false` is enough to switch a rule
    off, but an override that keeps a rule ENABLED must restate `hosts` and `action`,
    because there is nothing left to inherit them from. Field-level merge was considered
    and rejected — it would re-import the Phase 117 list-union narrowing limitation into
    `hosts`, so a leaf could never shrink an inherited host list.

    Ordering rule (pin it in the comment and in a test): the output keeps each name at
    the index of its first appearance and carries the body of its last appearance. Order
    matters because the sidecar matches first-match across the rule list, so a leaf must
    not be able to silently reorder a base's rules just by overriding one.

    `EnabledIntercepts` calls `CollapseIntercepts` first, then filters on
    `InterceptEnabled`. It is the accessor the compiler uses; make it idempotent and
    nil-safe so a non-extends profile (which never passes through Resolve) is still
    collapsed defensively.

    `DuplicateInterceptNames` returns, in first-appearance order, every name that appears
    more than once with at least two entries that are NOT `reflect.DeepEqual`. Identical
    repeats are not reported — the locked decision makes CONFLICTING content the error.
    Plan 04 consumes this.

    `ProfileIntercepts` is the nil-safe accessor: nil profile, nil `Spec.Network.MITM`,
    or nil `Intercepts` all return nil.

    Then wire the single integration point: in `fromMap` (pkg/profile/inherit.go), after
    the profile has been unmarshalled and before it is returned, replace
    `p.Spec.Network.MITM.Intercepts` with `CollapseIntercepts(...)` when the MITM block is
    non-nil. Add a comment explaining that this is why the merged bytes km validate
    inspects can never hold a duplicate name, and therefore why plan 04 can treat any
    duplicate it sees as a single-file typo. Do NOT drop disabled entries here — the
    resolved profile is also what gets written to the on-box profile file, and an
    operator reading it should see the rule that was switched off.

    Add `pkg/profile/mitm_test.go` covering every bullet in the behavior block above,
    table-driven where it reads naturally.
