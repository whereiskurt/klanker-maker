<objective>
Replace the compiled-in easter-egg handler in the http-proxy sidecar with a
generic, env-driven intercept engine: a host matcher with allowlist semantics, a
base64/JSON rule loader that fails toward zero rules, and handler registration at
exactly the position the hardcoded block occupies today.

Purpose: every host-matched behaviour in the proxy is currently compiled in.
This plan makes one class of them declarative without letting an operator rule
displace the handlers that carry real logic (token accounting, DynamoDB writes,
repo allowlisting).

Output: `intercept.go` with the matcher/loader/option/handlers, the hardcoded
block deleted, the transparent-listener path covered, and `main.go` reading the
new env var.
</objective>

    - `MatchIntercept` returns the FIRST matching rule when two rules both match.
    - `ParseIntercepts` round-trips a two-rule payload (one redirect, one respond) with every field intact.
    - `ParseIntercepts` round-trips a respond body containing interior spaces AND an embedded newline, byte for byte.
    - `ParseIntercepts("!!!not-base64!!!")` returns an error and a nil slice, no panic.
    - `ParseIntercepts` of valid base64 whose payload is not JSON returns an error and a nil slice, no panic.
    - `ParseIntercepts("")` returns a nil slice and no error.
    - `ParseIntercepts` drops (does not error on) an individual entry with zero hosts, an entry with neither redirect nor respond, and an entry with BOTH, while keeping the well-formed entries alongside them.
    - `InterceptResponse` for a redirect rule returns status 301 with a `Location` header equal to the declared URL.
    - `InterceptResponse` for a respond rule returns the declared status and the exact body, with `text/plain` used when contentType is empty.

  <action>
    Create `sidecars/http-proxy/httpproxy/intercept.go` in package `httpproxy` with the
    symbols listed in the artifacts section.

    `MatchesHost` reproduces `IsHostAllowed`'s semantics — `net.SplitHostPort` with an
    error meaning no port, `strings.ToLower` on both sides, a leading `.` matching the
    apex and any subdomain, otherwise exact equality — with ONE deliberate omission: it
    does not honour `*` as a match-all. State that omission and its reason in the doc
    comment: an intercept is a targeted rule, and a match-all intercept would terminate
    every request at the proxy while looking like a harmless allowlist idiom. Write the
    comment so a reader understands this is narrower than the allowlist matcher on
    purpose, and note that it is narrower than today's regex too — a suffix-extended
    lookalike of a declared host no longer matches, which is a bug fix, not a regression.

    `MatchIntercept` walks the slice in order and returns a pointer to the first rule
    whose `Hosts` match. First-match, so declaration order in the profile is the
    precedence order between intercepts.

    `ParseIntercepts` takes the raw env value. Empty string returns nil, nil. Otherwise
    `base64.StdEncoding.DecodeString` then `json.Unmarshal` into `[]Intercept`; either
    failure returns `nil, err` — the whole rule set is discarded, never half of it,
    because a partially-applied rule set could redirect traffic the operator never asked
    to redirect. After a successful unmarshal, drop any entry that cannot produce a safe
    action (zero hosts; neither redirect nor respond set; both set) and log a warn naming
    the rule; keep the rest. Use the JSON tags `name`, `hosts`, `redirect`, `respond`,
    and on Respond `status`, `contentType`, `body` — this is the wire contract plan 03
    must produce, so state it in the type's doc comment.

    `WithIntercepts` follows `WithDeniedHosts`: a nil or empty slice sets nothing (so the
    option is a no-op and registration never happens), otherwise it stores the slice on
    `proxyConfig`.

    `InterceptResponse` builds the response with `goproxy.NewResponse`. Redirect form:
    status 301, content type `text/html; charset=utf-8`, a short generic moved-permanently
    body naming the target as an anchor, and the `Location` header set to the target.
    Note in the comment that the previous hardcoded handler also emitted a fake upstream
    `Server` header to imitate the intercepted site; that cosplay is deliberately not
    reproduced, so the response now honestly identifies as a proxy-generated one. Respond
    form: `goproxy.NewResponse(req, contentType, status, body)` with contentType
    defaulting to `text/plain` when empty.

    `registerInterceptHandlers` registers exactly two handlers on the passed proxy — one
    `OnRequest().HandleConnectFunc` returning `goproxy.MitmConnect, host` on a match and
    `nil, host` on a miss, and one `OnRequest().DoFunc` returning `req,
    InterceptResponse(...)` on a match and `req, nil` on a miss. Both must fall through on
    a miss; the deny gate in `NewProxy` is the model to copy. Log one line per intercepted
    request from the DoFunc with `event_type` `mitm_intercept` plus `sandbox_id`,
    `intercept` (the rule name), `host`, and `action` (`redirect` or `respond`). Do not
    log from the CONNECT handler — one event per intercepted request, same shape as the
    handler being replaced.

    Add `intercept_test.go` covering every bullet in the behavior block. The
    suffix-extension negative and the spaces-and-newline body round-trip are both
    mandatory and must not be weakened into a shape that would pass without the property
    they exist to prove — a body round-trip with no whitespace in it proves nothing about
    the transport this design chose base64 for.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| systemd env → proxy process | An untrusted-shaped base64 blob is decoded into rules that steer request handling. |
| sandbox → proxy | Sandbox-originated requests reach handlers whose ordering decides whether metering and deny enforcement apply. |
| proxy → upstream | An intercepted request is terminated at the proxy and never leaves the box. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-127-01 | Elevation of Privilege | handler registration order in `NewProxy` | high | mitigate | Intercepts register after the deny gate, the metering handlers, and the GitHub repo filter; three end-to-end tests assert the client-visible response, not the registration order. |
| T-127-02 | Tampering | `MatchesHost` | high | mitigate | Exact/leading-dot matching with no regex and no `*` wildcard; the suffix-extension case that today's unanchored pattern gets wrong is pinned by a negative test. |
| T-127-03 | Denial of Service | `ParseIntercepts` | medium | mitigate | Decode failure discards the whole rule set and the proxy still starts with working egress; no fatal path, negative test for garbage input. |
| T-127-04 | Spoofing | `InterceptResponse` redirect body | low | mitigate | The imitation upstream `Server` header is dropped, so an intercepted response no longer impersonates the site it replaced. |
| T-127-07 | Repudiation | intercept logging | low | mitigate | One `mitm_intercept` event per intercepted request carrying rule name, host, and action, on both the goproxy and transparent paths. |
| T-127-SC | Tampering | npm/pip/cargo installs | high | accept | No package installs and no new dependency in this plan; the Package Legitimacy Gate has nothing to audit. |
</threat_model>
